CONTINUATION HANDOFF PROMPT — TEMPLATE (ADR-023)
================================================
This is the fill-in template for the paste-into-a-new-window continuation prompt
generated by `/mxm-handoff` and the `/mxm-session-end` Phase-4 step.

WHY THIS SHAPE (the anti-hallucination contract — ADR-023):
A handoff prompt fails when it embeds facts that go stale (git HEADs, capability
counts, "what's done"). The next window trusts the prose, the prose is wrong, and
it hallucinates from there. This template does the opposite: it POINTS to the
source of truth and FORCES verification before any action. The embedded snapshot
is explicitly labelled "unverified — the files win." That single rule is what makes
a fresh window continue cleanly instead of confidently-wrong.

GENERATOR RULES (the skill filling this in MUST follow these):
  1. Every {{PLACEHOLDER}} is replaced from VERIFIED session state only — never guessed.
     If a value was not verified this session, write "UNVERIFIED — read <source> first",
     not a plausible-looking value. (Global rule: never hallucinate; mark assumptions.)
  2. Do NOT inline capability counts, full rosters, or long file contents. Point to the
     ledgers/source-of-truth files instead — they cannot go stale the way a paste can.
  3. Keep the SNAPSHOT block short. Its only job is orientation; VERIFY STATE re-derives truth.
  4. Carry forward the operator's open DECISIONS verbatim and flag them as "do NOT decide for him".
  5. This is a cousin of `auto-compact.md` (in-place compaction). This artifact is for a
     FRESH window / new chat; auto-compact's compact-seed is for same-conversation compaction.

Runtime output path: .claude-sessions-memory/CONTINUATION-PROMPT.md (gitignored, runtime-local).
-->
